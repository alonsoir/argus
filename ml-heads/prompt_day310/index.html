    Reglas de trabajo (las de siempre)

    Medir, no votar; predicción escrita antes de medir; si algo no da lo esperado, PARAR, y si una corrida falla no se sigue con el paso siguiente. Antes y después en cada paso. Comandos exactos y completos, en orden, diciendo dónde se ejecuta cada uno (Mac / defender / client), con la salida a fichero + ; cat. Ficheros generados como descarga con sha256 (se guardan desde ~/Downloads con mv). Parcheadores que validen TODO antes de escribir NADA (sha256 de partida y de llegada, anclas únicas, "ya aplicado", --check/--apply), probados por Claude en una copia desechable antes de entregarlos; los parcheadores de un solo uso no se commitean, los instrumentos de medida sí. git grep, nunca grep -rn .; inventarios sin truncar, volcados a fichero y contados. awk con LC_ALL=C. El JSON es la ley: se lee siempre; si un campo falta o está mal formado, defecto (igual al del JSON) + aviso, y el log dice por cada campo el valor y si sale del JSON o del defecto. Leer el fichero entero antes de parchear. Compilar siempre el pipeline completo en producción (make pipeline-build PROFILE=production); diagnósticos con grep -E ':[0-9]+:[0-9]+: (warning|error):'; pruebas con make test-components PROFILE=production comprobando las cinco líneas de resumen. Las tareas del Makefile que no estén duplicadas se quedan. No se mantiene código deprecado: se borra. Las secciones de un documento escritas antes de medir no se reescriben: el resultado va aparte.

    Lecciones de DAY309

    • Antes de predecir lo que mide un test, leer el código que prueba, no solo el test.
    • Un inventario se saca contra el fichero, no se hereda de la lista de una deuda (eran 5 tests sin registrar, no 3).
    • pgrep -f / pkill -f se encuentran a sí mismos cuando su línea de comandos contiene el patrón: un servicio se vigila por su puerto y se para por su PID.
    • Un comprobador se lee por su texto, no por su código de salida: un fallo no capturado de Python sale con rc 1.
    • Un criterio relativo no sirve con base 0: para positivos aislados se predice una cuenta absoluta.
    • Un análisis que agrupa por origen filtra también por protocolo (el ping de fondo de "esperar ESTABLE" sale de .50).
    • Un tail corto puede cortar justo lo que importa: el análisis va a fichero y se lee entero.
    • Una diferencia de decisiones se investiga con hipótesis escritas antes de mirar y un instrumento que reproduzca la decisión fila a fila; así se separó "efecto de la rama" de "etapa 1 en el borde de K".
